# 安全员工作台（单机离线 · 空白版）

面向企业安全管理人员（EHS / 安全员）日常办公的单页工作台：一个页面集中呈现安全待办、隐患治理与统计数据。

**本版本是「空白单机版」**：项目内已彻底移除示例数据、模拟数据、演示开关与占位内容，首次打开即为空白初始状态，所有数据由用户自己录入。

- **零构建、零外链**：无 npm、无打包、无 CDN、无外部字体与图表库，图标和图表全部内联 SVG
- **双击即用**：直接打开 `index.html` 就能跑（无需起服务）；断网可用，全程不发任何网络请求
- **空白初始状态**：不带任何示例记录，九个模块打开都是空态 + 录入引导
- **数据不出本机**：改动存 localStorage，支持导出 / 导入 JSON 备份；「清空数据」需输专用密码后恢复空白
- **接口可后接**：数据访问走 DataSource 适配层，将来接真实后端只改 `config.js`，界面不动

### 分层与调用方向（严格遵守单向，禁止成环）

```
数据层  store.js / dataSource.js
          ↓  被读取
计算层  metrics.js        ← 纯函数，只算一次，结果放 state.summary
          ↓
装配层  app.js refreshAll()   ← 唯一刷新入口
          ↓
视图层  views/*.js        ← 只读 ctx.summary，不取数、不互相调用
```

任何交互都只允许「改数据 → 调 `refreshAll()` 或 `reload()`」，
**绝不允许在某个 `render()` 内部直接调用另一个 `render()`**。

## 二、使用方法

1. 双击 `index.html`（或拖进浏览器）。**首次打开即为空白工作台**——所有模块都是空态，从「登记第一条隐患」开始用。
   **打开即为「受限用户」**：只能看，不能改；需要写数据时页面会弹密码框，输对六位安全员密码即解锁
   （初始密码 `123456`，请第一时间在「⋯ → 密码设置 / 修改」里改掉）。详见 README「二·十七、受限用户 + 六位安全员密码 + 右上角设置 + 左上角品牌自定义」。
2. 右上角「⋯」设置菜单（点齿轮展开）：
   - **导入 / 导出**：JSON 备份与恢复（导入支持全量数据，无条数上限）
   - **清空数据**：**必须再输入「清空数据专用密码」**（默认 `888888`，与登录密码分开）才会执行；密码不对直接拦下并提示，数据一点不动（建议先导出备份）
   - **角色**：`安全员（全权）` / `受限用户` 下拉切换（切到安全员要过密码；切回受限立刻收权）
   - **密码设置 / 修改**：改六位安全员密码（先验证旧密码）
   - **工作台外观（图标 / 名称）**：同下条
3. 左上角品牌区（图标或文字，点一下即可改）：
   - 图标：内置图标库里挑，或上传自己的图片（转成 dataURL 存在本机）
   - 名称 / 副标题：随手改；名称会同步到浏览器标签，并随「导出」备份一起保存；留空会被拦截
4. 手机 / 平板：响应式三档 —— ≥1024 导航常驻，768~1023 收成图标条，<768 变底部 Tab。
   用系统浏览器打开后「添加到主屏幕」即可当 App 用。

> 单机离线保证：页面不引用任何外部资源（无 CDN / 字体 / 图表库 / 接口），
> 所有读写都发生在本机浏览器；断网、内网、保密环境均可正常使用。

## 二·六、隐患整改通知书打印

版式**逐格照抄企业现行《事故隐患整改通知书》**（参数实测自 `事故隐患整改通知书（26.9.8）.docx`）：

| 项 | 取值 | 来源 |
|---|---|---|
| 纸张 | A4 纵向 210×297mm | 原件 pgSz 11906×16838 dxa |
| 页边距 | 上 20.4 / 下 13.8 / 左右 24.8 mm | ★ 与「保存的 Word 件」实测一致：pgMar 1157 / 781 / 1406 / 1406 dxa（2026-10-22 用户给的《事故隐患整改通知书（2026.10.22）.docx》） |
| 表体 | 单表 10 行，两列 **7.8% : 92.2%** | 与保存页一致：720 : 8520 dxa（原 11.9/88.1 与 Word 件不一致，10-22 已对齐）；原第 2 行「检查日期+检查单位」按要求拆成两行 |
| 字号 | 标题 22pt｜检查日期·检查单位·责任单位 14pt｜图片区左 22pt（竖排）右 12pt｜领导批示·底部四行 15pt | 原件 sz 44 / 28 / 44·24 / 30 |
| 行高 | 39 / 32 / 32 / 33 / 330 / 97 / 33 / 33 / 33 / 34 pt | 原件 trHeight ÷ 20；拆开后两行合计 64pt ≈ 原件 65pt |
| 边框 | 全框线 0.5pt | 原件 tblBorders sz=4 |

> **「领导批示」四个字从上到下竖排**（class `pn-lab2`，15pt，每字一行）。
> 左列只有 7.8%（≈11mm），横排放不下：屏幕每字一个块级 `<span>`（`.pn-lab2 span{display:block}`），
> Word 保存页每字一段。高度：4 × 15pt × 1.2 ≈ **72pt < 批示行 97pt**，竖排不溢出。
> `.pn-lab2` 需显式 `writing-mode:horizontal-tb` 覆盖 `.pn-lab` 的 `vertical-rl`——
> 竖排书写模式下块级元素会按从右往左排成四列（2026-10-22 实测）。

> **★ 2026-10-22 起：屏幕预览 / 浏览器打印 / Word 保存页三处版式统一。**
> 预览页不再用 CSS 硬压照片，改由 `printNotice.fitPhotos` 复用保存页的 `layoutPhotos`
> 算法写出 pt 尺寸，逐张与保存页一致；照片一律排在正文**之上**。

> **★ 打印走独立样式 `assets/css/print-only.css`**（`<link media="print">` 单独引入）：
> · 只管出件、不参与屏幕渲染；`@page` A4 + 上 20.4 / 左右 24.8 / 下 13.8mm，纸张自身 padding 归零；
> · 隐藏工具条 / 导航 / 侧栏 / 按钮 / 提示条 / 删除键等非打印元素；
> · 表体左缩进 4.76mm（Word 件 tblInd 270 dxa），宽度取「可印区 − 缩进」，右侧不被裁；
> · 防截断 + 能分页：单元格 `overflow:visible`、短行 avoid、照片行允许跨页、单张照片不切断。

**字段自动带出**（可现场改）：

| 通知书栏目 | 数据来源 |
|---|---|
| 检查日期（第 2 行，独占） | `hazard.foundDate`（转中文：2026年9月8日） |
| 检查单位（第 3 行，独占，不与日期同行） | 可配，默认「安全环保部」，改后存 localStorage 沿用 |
| 事故隐患整改责任单位 | `hazard.dept` |
| 事故隐患图片及部位 | `location` + `title` + `measure` 自动成文，附现场照片 |
| 要求整改完工日期 | `hazard.dueDate`（当前期限） |
| 整改责任人 | **留白**，纸质件上手写（下发时现场填） |
| 整改完工验收单位 | **留白**，纸质件上手写（配置值仅用于正文「报××验收」字样） |
| 领导批示 / 验收人 | 留白，纸质件上手写 |

**使用**

1. 隐患管理 → 操作列「操作 ▾」→「整改通知书（打印/Word）」，或打开隐患详情 →「打印整改通知书」
2. 预览页顶部可改检查单位 / 验收单位（下次默认沿用）、上传现场照片（≤3 张，自动压到 1000px，存进隐患台账 `photos`）。
   「验收单位」只影响正文那句「整改完成后报××验收」，纸面验收单位栏留白手写
3. 正文可直接点开改（contenteditable），改完再出件
4. **打印**：浏览器打印对话框，纸张已按 A4 排版；**出件后自动写一条流转留痕**（可取消勾选）。
   对话框若出现网址/日期/页码，在「更多设置」里取消「页眉和页脚」——这是浏览器行为，CSS 关不掉
5. **保存为 Word**：生成 `.docx`（真 OOXML，Word / WPS 直接打开、可再编辑），
   文件名 **`事故隐患整改通知书（2026.10.22）.docx`**（出件当天日期，月日不补零）；
   ★ **不加任何后缀**：同一天再出第二份也叫同一个名字。
   ★ 文件名里**不带隐患编号**（纸质件归档不暴露内部编号）。

> **不写编号 / 等级 / 类型**——这些是内部管理信息，留在系统台账里，纸质件只给责任单位签收执行。

**留痕内容**：`下发《事故隐患整改通知书》：要求 {责任部门} 于 {期限} 前完成整改，责任人 {责任人}。`

### 照片怎么存：不压缩 + 大图外置（2026-10-24）

**为什么改**：培训 / 隐患照片要能下载原图取证，压到 1000px 会丢细节。但浏览器 localStorage 每个源只有约 **5MB**，
一张手机照 3~6MB，两三张就写不进去（会报「本地存储已满」）。

**做法**（`components/photoVault.js`，对视图代码零侵入）：

- **落盘时**：业务数据里所有 `data:image/...` 且长度 > 30KB 的字符串，写进 **IndexedDB**，JSON 里只留 `vault:<key>` 引用
  → localStorage 只剩几十 KB，容量上限从 5MB 变成 IndexedDB 的几百 MB
- **启动时**：把 `vault:<key>` 全部换回 dataURL → 内存里仍是完整图片，**视图 / 打印 / 水印 / 导出照旧拿 dataURL，一行没改**
- 同一张图按内容指纹复用同一个 key，重复保存不会堆积
- 「清空数据 / 重置示例」时一并清空仓库，不留孤儿

**降级与兜底**：
- 浏览器不支持 IndexedDB（如隐私模式）→ 自动退回「整包写 localStorage」，行为与以前一致
- 引用丢了（换浏览器、清过站点数据）→ 显示「照片丢失」占位图，**不破图、不崩页**

**导出备份**：备份 JSON 里是**完整原图**，文件会明显变大（几条带照片的记录可能几十 MB），属正常现象。

**历史照片**：2026-10-24 之前上传的是压缩版，**无法还原成原图**；新上传的才是手机原图。

## 二·十三、证件图片识别（接公司 OCR 接口，2026-10-24）

**做什么**：特种作业人员台账 →「操作 ▾ → 编辑」→ 弹窗顶部点 **「识别图片」**，
自动读「证件照」里第一张图上的文字，把姓名 / 作业类别 / 操作项目 / 证书编号 / 发证机关 /
有效期起止 / 复审日期 **直接填进对应字段**，填完可逐项手改。

**为什么需要接口**：本项目是零依赖的离线单页，浏览器本身没有中文 OCR 能力（体积与离线要求也放不下）。
所以识别这一步交给一个 HTTP 接口，拿到文字后由本地规则 `components/ocr.js` 拆成字段——**解析这一步断网也能跑**。
接口有两种来源，二选一，页面代码完全不用改：
- **本机离线服务（默认，开箱即用）**：随项目附带的 `tests/local_ocr_server.py`（RapidOCR 模型，纯 CPU、不联网）
- **公司 OCR 接口**：腾讯云 / 百度 / 内网 OCR，配置见下方第 1 节

### 0) 开箱即用：本机离线识别服务（推荐，零成本、不联网）

```bash
# 首次装依赖（约 100MB，模型随包内置）
python -m pip install rapidocr-onnxruntime -i https://mirrors.aliyun.com/pypi/simple/
python -m pip install "onnxruntime==1.20.1"        # 重要：1.21+ 在本机会 DLL 初始化失败

# 启动服务（只监听 127.0.0.1:8123，不对外、不上传图片）
python tests/local_ocr_server.py
```

- 启动后打印 `本地识别服务已启动：http://127.0.0.1:8123`，**用页面期间保持窗口开着**
- 页面 `config.js` 已指向它（`endpoint: 'http://127.0.0.1:8123/ocr'`），不用再改
- 探活：`http://127.0.0.1:8123/health` 应返回 `{"ok":true,...}`
- 停止：窗口按 `Ctrl+C`；换端口：`set OCR_PORT=8124` 再启动
- 实测：模型加载 0.6s，单张证件约 1~2.5 秒；整页截图约 4~5 秒

> 本机服务与公司接口是同一套约定（`POST /ocr {"image": base64}` → `{"text": "..."}`），
> 以后公司接口就绪，只把 `endpoint` 换掉即可。

### 0.5) 一键启动：页面按钮直接拉起服务（注册一次，推荐）

不用再记着「先开一个窗口」：页面会自己把服务拉起来。

```bash
# 一次性注册（写 HKCU，不需要管理员；随时可卸载）
双击 tests/install_ocr_protocol.bat
```

之后在 **特种作业人员 →「操作 ▾ → 编辑」** 弹窗顶部：

| 状态点 | 含义 | 你能做什么 |
|---|---|---|
| ● 识别服务在线（绿） | `/health` 通 | 直接点「识别图片」 |
| ● 识别服务未启动（红） | 服务没跑 | 点旁边的 **「启动服务」**；或直接点「识别图片」，会先自动拉起再识别 |
| ● 正在启动识别服务（黄闪） | 正在拉起 / 等就绪 | 等 2~4 秒，状态自动变绿 |
| ● 公司识别接口（蓝） | 用的是外网接口 | 不探活、不启动，行为与以前一致 |
| ● 未配置识别接口（红） | `endpoint` 为空 | 去 `config.js` 填接口地址 |

**原理**：注册了 `safetyocr://` 自定义协议 → 页面在点击的同步栈里触发协议 →
Windows 执行 `start_ocr_silent.bat`（已在运行就直接退出，不会起第二份；最小化窗口，日志写 `_ocr_server.log`）→
页面轮询 `/health`，就绪后自动继续识别（默认最多等 25 秒）。

**日常操作**：
- 停止服务：双击 `tests/stop_ocr.bat`（静默启动没有窗口可关）
- 卸载一键启动：双击 `uninstall_ocr_protocol.bat`（识别本身不受影响，改回双击 `start_ocr.bat` 手动启动）
- 协议没注册：点「启动服务」会在 25 秒后明确提示「去双击 install_ocr_protocol.bat 或 start_ocr.bat」，不会静默失败
- 换机器 / 换 Python 环境：重新双击 `install_ocr_protocol.bat`（自动记录当前 Python 路径到 `_python.txt`）

### 1) 配置（一处，改完即生效）

`assets/js/config.js` → `SD.CONFIG.ocr`：

| 字段 | 说明 |
|---|---|
| `endpoint` | 识别接口地址。**默认已填本机服务** `'http://127.0.0.1:8123/ocr'`；换公司接口就改成 `'/api/ocr'`（同域）或 `'https://gw.company.com/ai/ocr'`。**留空 = 未配置**：按钮仍在，点击会明确提示来这里配，不会静默失败 |
| `mode` | `'json'`（默认，base64 走 JSON）或 `'form'`（multipart 上传文件） |
| `fieldName` | 图片字段名，默认 `image` |
| `headers` | 鉴权头，例 `{ Authorization: 'Bearer xxx' }` |
| `textPath` | 返回 JSON 里文字所在路径，默认 `text`；若是 `{data:{text}}` 就填 `data.text` |
| `extra` | 需要随图上传的额外参数（并入 json body） |
| `timeout` | 识别超时，默认 15s（比普通接口慢，单独给） |

### 2) 接口约定（默认 json 模式）

```
POST  {endpoint}
Content-Type: application/json          (+ headers 里的鉴权头)
Body  { "image": "<base64，不含 data: 前缀>" }

返回  { "text": "识别出的整段文字" }
```

返回结构不用改也能用（已做兜底）：`{data:{text}}`、`{result:{text}}`、
百度的 `{words_result:[{words}]}`、腾讯整页识别的 `{data:{text_lines:[{text}]}}`、
以及纯文本响应都可以。**换服务商只改 config，不改代码。**

> ⚠️ **跨域**：页面会直接从浏览器请求该接口，接口必须允许页面来源（`Access-Control-Allow-Origin`），
> 否则会被浏览器拦（控制台报 CORS）。最省事的是把接口和页面放同域（如 `/api/ocr` 反向代理到 OCR 服务）；
> 也**不要在页面里放云厂商的 SecretKey**，签名放后端做。

### 3) 识别不到时怎么办

- 没上传证件照 → 提示「请先在「证件照」里添加一张证件图片」；
- 没配接口 → 提示去 `config.js` 配 `endpoint`；
- 接口报错 / 超时 / 返回没文字 → 弹出具体原因（HTTP 码、超时、返回结构），提示条里也留一行；
- 识别到文字但没匹配上字段 → 明确说「没匹配到台账字段」，提示换一张正面清晰照。

**绝不静默**，也**绝不伪造识别结果**：所有填入的都是接口真实返回并经本地规则解析的值。

### 为什么以前一页装不下（2026-10-25 定位的三个原因，已修）

参考表是 Excel，它在文件里存了 `fitToPage`，**打印那一刻**会把整张表等比缩到 83.6% 塞进一页；
浏览器没有这个机制，必须靠 CSS 的布局级缩放自己算。以前不行是因为三件事叠加：

| # | 原因 | 实测证据 |
|---|---|---|
| 1 | **纸张误用了通知书的 `.pn-sheet` 类**。`print.css` 在 `components.css` 之后加载、优先级相同，把 `.sl-sheet` 的 `248mm 宽 / 0 内边距 / 160mm 最小高` 覆盖成 `210mm / 24.8mm / 297mm` | 纸张实测 **794×1230px = 210×325mm**（A4 纵向比例），表格被挤到 160mm 宽，文字大量折行，需要缩到 53% 才勉强塞下 |
| 2 | **缩放把「只改画面」的 `transform` 当成了首选**。原来用 `scrollHeight` 判断 `zoom` 是否生效，而 Chrome 里加了 `zoom` 后 `scrollHeight` **仍报未缩放值** → 永远判成"不支持" → 退回 `transform`。`transform` 不改布局，打印分页仍按原尺寸算 | 同一份 DOM：`zoom` 输出 **1 页**，`transform` 输出 **2 页**（真打印 PDF 数页数） |
| 3 | **行高被全局行距撑高**。`base.css` 的 `line-height:1.55` 让 11pt 文字行盒 22.7px，加 1.4mm 上下内边距 → 每行撑到 **26pt**（应为 24pt），19 行多出 38pt；另有 3 个 4 字分组名（危化品区/发泡区域/特种设备）在 9 字符宽的 B 列里差 0.3px 就折行，各多 12pt | 逐行量：19 行里有 3 行是 49px(36.75pt)、其余 32px(24pt)，总高 850px（应为 777px） |

修完实测（真打印成 PDF，数页数）：纸张 **964×795px = 255×210mm**、缩放 **80%** → **1 页 / A4 横向（297×210mm）**，
19 行 + 抬头 + 表尾注 + 备注全部在页内，无截断。

**★ 2026-10-25 修掉的第四个真 bug**（保存页「漏了班次和时间」的根因）：
抬头行第一个格子 `mergeAcross:2` 合并成 A:C，而后面的「班次」「日期」两个格子**仍按顺序落到 B、C 列**，
正好被合并一口吃掉 —— 导出的表里只剩厂区/部门/巡检人员。现在 `xlsxWriter` 支持单元格显式列位
`cell.col`（0 起），这两个格子钉在 D、E 列，`mergeAcross` 也算它们自己的位置，不会再被吞。

**★ 2026-10-25 修掉的三个真 bug**（都是出件"内容缺失 / 错位 / 少边框"的根因）：

1. **后半张表整体左移一格**：检查项列、备注列被纵向合并的行少 push 了格位，
   而 `xlsxWriter` 是按数组顺序往 A/B/C… 落的 → 从第 2 组开始「检查内容」跑到 B 列、「检查情况」跑到 C 列，
   D / E 两列连单元格都没有（既错位又缺右边框）。现在被合并掉的列一律补 `{v:'', border:true}` 占位格，
   **19 个明细行每行都占满 A~E 五格**，自检逐行核对列位。
2. **明细行行高把长内容截掉**：原表一律 20.5pt，但最长的两条检查内容（特种设备 / 电气）一行放不下。
   现在按估算行数放宽（放不下就给 36pt），**宁可高一点也不丢字**。
3. **第一个用到的样式被丢**：`xlsxWriter` 的样式索引从 0 起，而写出时只在 `s>0` 时写 `s` 属性 →
   第一格（正好是标题）的 16pt 加粗居中全部失效。现在 0 号留给默认样式，实际样式从 1 号开始。

另外按你的要求：**标题行与厂区行（抬头行）在界面、打印件、导出件三处都是「无边框 + 居中」**。

**权限**：受限用户也能**看、打印、导出**；只有安全员能改检查情况与备注（受限态下下拉是禁用的，顶部有「只能查看」提示）。

**字段**（`data/schema.md` 的 `shiftLogs`）：`id / date / shift / inspector / checks[]（19 项，每项 '' / 'ok' / 'bad'）/ events[]（备注事件文本数组）/ updatedAt`。

**自检**：`node tests/smoke_shift.js [url]` —— **153 项**。

## 二·十七、受限用户 + 六位安全员密码 + 右上角「⋯」设置 + 左上角品牌自定义（2026-10-25）

### 1) 进来默认是受限用户

**打开工作台就是「受限用户」** —— 能看、能打印、能导出 Excel，但**不能新增 / 修改 / 删除**，
也进不了特种作业模块、导不进数据、改不了密码。右上角角色徽标显示「🔒 受限模式」。

**解锁**：点右上角「受限模式」徽标，或直接在任意受限操作上触发 —— 弹出密码框，输入**六位安全员密码**即进入安全员权限。

| 项 | 值 |
|---|---|
| 初始密码 | **`123456`** —— 请第一时间改掉（还在用默认密码时页面会提示） |
| 生效范围 | 只对**本次打开**有效（存 sessionStorage）。关掉浏览器再进，又回到受限，避免「解一次就永久敞开」 |
| 存哪 | 本机 localStorage 只存**加盐摘要**（`salt + hash`），**不存明文**；密码校验与角色判定都在 `assets/js/auth.js` |

**四种能力点**（`SD.auth.can(perm)`）：`data.read`（浏览，受限也有）、`data.write`（增删改）、
`special.view`（特种作业）、`settings.write`（导入 / 清空 / 改密码）。

> ⚠️ 这是**本机前端门禁**，用途是防误操作、防顺手改数，**不是网络安全**。
> 真系统里把权限判定放后端即可，`can()` 的调用点一处不用改。

### 2) 右上角「⋯」设置菜单

点齿轮展开，六项：**导入数据 / 导出备份 / 清空数据 / 角色（安全员 ↔ 受限） / 密码设置・修改 / 工作台外观（图标・名称）**。

### 3) 左上角图标与文字可自定义

点左上角**图标或工作台名称**任意一处，或走「⋯ → 工作台外观」：

- **图标**：内置图标库挑一个，或**上传自己的图片**（转 dataURL 存本机，随备份一起导出）
- **名称 / 副标题**：随手改，名称同步到浏览器标签；名称留空会被拦截
- 保存在 `settings.appIcon / appName / appSubtitle`，随「导出备份」一起走

**自检**：`node tests/smoke_shift.js [url]` 的第 1 / 4 / 8 / 9 / 10 / 11 节覆盖以上全部行为（**153 项**里的角色与设置部分）。

### 4) 清空数据 = 专用密码（2026-10-25 新增）

「清空数据」是**不可撤销**的操作，所以除了要安全员权限，还要再过一道**专用密码**：

| 项 | 值 |
|---|---|
| 初始专用密码 | **`888888`** —— 与登录密码**相互独立**，改登录密码不影响它 |
| 存在哪 | 另一条独立的加盐摘要记录（localStorage `sd_auth_purge`），与登录密码分开 |
| 密码错 | **不执行**：弹窗不关、顶部红字「专用密码不正确：已阻止清空，数据没有任何改动」，**一条数据都不会动** |
| 位数不对 | 同样拦下（提示「请输入 6 位数字的专用密码」） |
| 改在哪 | 「⋯ → 密码设置 / 修改」弹窗下半部分，可单独改（与登录密码相同会被拒） |
| 代码位置 | `auth.js` 的 `verifyPurge / setPurgePin / hasPurgePin`，`app.js` 的 `openPurgeDialog()` |

### 5) 连续 30 分钟无操作 → 自动退回受限（2026-10-25 新增）

复核完忘了收权是最常见的漏洞。现在有**空闲看门狗**：

- 计时口径：鼠标 / 键盘 / 触摸 / 滚轮 / 滚动**任一操作**都会重新计时；连续 **30 分钟**没有任何操作即自动 `lock()`（退回受限）。
- 只在**安全员**状态下生效；受限本来没权限，不会重复触发。
- 切回浏览器标签页时立刻补判一次（后台标签页的定时器会被浏览器节流）。
- 退回时会 toast 提示「已连续 30 分钟无操作，自动退回受限模式」，右上角徽标同步变回「🔒 受限模式」。
- 阈值在 `config.js → security.idleLockMin`（分钟，**填 0 = 关闭**）；代码在 `app.js` 的
  `startIdleWatch / checkIdle`，也可用 `SD.app.idle.check()` 手动触发（自检就是这么测的）。

|---|---|
