# 安全员工作台（单机离线 · 空白版）

面向企业安全管理人员（EHS / 安全员）日常办公的单页工作台：一个页面集中呈现安全待办、隐患治理与统计数据。

**本版本是「空白单机版」**：项目内已彻底移除示例数据、模拟数据、演示开关与占位内容，首次打开即为空白初始状态，所有数据由用户自己录入。

- **零构建、零外链**：无 npm、无打包、无 CDN、无外部字体与图表库，图标和图表全部内联 SVG
- **双击即用**：直接打开 `index.html` 就能跑（无需起服务）；断网可用，全程不发任何网络请求
- **空白初始状态**：不带任何示例记录，九个模块打开都是空态 + 录入引导
- **数据不出本机**：改动存 localStorage，支持导出 / 导入 JSON 备份；「清空数据」需输专用密码后恢复空白
- **接口可后接**：数据访问走 DataSource 适配层，将来接真实后端只改 `config.js`，界面不动

### 分层与调用方向（严格遵守单向，禁止成环）

```
数据层  store.js / dataSource.js
          ↓  被读取
计算层  metrics.js        ← 纯函数，只算一次，结果放 state.summary
          ↓
装配层  app.js refreshAll()   ← 唯一刷新入口
          ↓
视图层  views/*.js        ← 只读 ctx.summary，不取数、不互相调用
```

任何交互都只允许「改数据 → 调 `refreshAll()` 或 `reload()`」，
**绝不允许在某个 `render()` 内部直接调用另一个 `render()`**。

## 二、使用方法

1. 双击 `index.html`（或拖进浏览器）。**首次打开即为空白工作台**——所有模块都是空态，从「登记第一条隐患」开始用。
   **打开即为「受限用户」**：只能查看与打印，不能导出、不能改；需要写数据或导出时页面会弹密码框，输对六位安全员密码即解锁
   （初始密码 `123456`，请第一时间在「⋯ → 密码设置 / 修改」里改掉）。详见 README「二·十七、受限用户 + 六位安全员密码 + 右上角设置 + 左上角品牌自定义」。
2. 右上角「⋯」设置菜单（点齿轮展开）：
   - **导入 / 导出**：JSON 备份与恢复（导入支持全量数据，无条数上限）；受限态下「导出备份」仍可点，会先要六位密码
   - **清空数据**：**必须再输入「清空数据专用密码」**（默认 `888888`，与登录密码分开）才会执行；密码不对直接拦下并提示，数据一点不动（建议先导出备份）
   - **角色**：`安全员（全权）` / `受限用户` 下拉切换（切到安全员要过密码；切回受限立刻收权）
   - **密码设置 / 修改**：改六位安全员密码（先验证旧密码）
   - **工作台外观（图标 / 名称）**：同下条
3. 左上角品牌区（图标或文字，点一下即可改）：
   - 图标：内置图标库里挑，或上传自己的图片（转成 dataURL 存在本机）
   - 名称 / 副标题：随手改；名称会同步到浏览器标签，并随「导出」备份一起保存；留空会被拦截
4. 手机 / 平板：响应式三档 —— ≥1024 导航常驻，768~1023 收成图标条，<768 变底部 Tab。
   用系统浏览器打开后「添加到主屏幕」即可当 App 用。

> 单机离线保证：页面不引用任何外部资源（无 CDN / 字体 / 图表库 / 接口），
> 所有读写都发生在本机浏览器；断网、内网、保密环境均可正常使用。

## 二·六、隐患整改通知书打印

版式**逐格照抄企业现行《事故隐患整改通知书》**（参数实测自 `事故隐患整改通知书（26.9.8）.docx`）：

| 项 | 取值 | 来源 |
|---|---|---|
| 纸张 | A4 纵向 210×297mm | 原件 pgSz 11906×16838 dxa |
| 页边距 | 上 20.4 / 下 13.8 / 左右 24.8 mm | ★ 与「保存的 Word 件」实测一致：pgMar 1157 / 781 / 1406 / 1406 dxa（2026-10-22 用户给的《事故隐患整改通知书（2026.10.22）.docx》） |
| 表体 | 单表 10 行，两列 **7.8% : 92.2%** | 与保存页一致：720 : 8520 dxa（原 11.9/88.1 与 Word 件不一致，10-22 已对齐）；原第 2 行「检查日期+检查单位」按要求拆成两行 |
| 字号 | 标题 22pt｜检查日期·检查单位·责任单位 14pt｜图片区左 22pt（竖排）右 12pt｜领导批示·底部四行 15pt | 原件 sz 44 / 28 / 44·24 / 30 |
| 行高 | 39 / 32 / 32 / 33 / 330 / 97 / 33 / 33 / 33 / 34 pt | 原件 trHeight ÷ 20；拆开后两行合计 64pt ≈ 原件 65pt |
| 边框 | 全框线 0.5pt | 原件 tblBorders sz=4 |

> **「领导批示」四个字从上到下竖排**（class `pn-lab2`，15pt，每字一行）。
> 左列只有 7.8%（≈11mm），横排放不下：屏幕每字一个块级 `<span>`（`.pn-lab2 span{display:block}`），
> Word 保存页每字一段。高度：4 × 15pt × 1.2 ≈ **72pt < 批示行 97pt**，竖排不溢出。
> `.pn-lab2` 需显式 `writing-mode:horizontal-tb` 覆盖 `.pn-lab` 的 `vertical-rl`——
> 竖排书写模式下块级元素会按从右往左排成四列（2026-10-22 实测）。

> **★ 2026-10-22 起：屏幕预览 / 浏览器打印 / Word 保存页三处版式统一。**
> 预览页不再用 CSS 硬压照片，改由 `printNotice.fitPhotos` 复用保存页的 `layoutPhotos`
> 算法写出 pt 尺寸，逐张与保存页一致；照片一律排在正文**之上**。

> **★ 打印走独立样式 `assets/css/print-only.css`**（`<link media="print">` 单独引入）：
> · 只管出件、不参与屏幕渲染；`@page` A4 + 上 20.4 / 左右 24.8 / 下 13.8mm，纸张自身 padding 归零；
> · 隐藏工具条 / 导航 / 侧栏 / 按钮 / 提示条 / 删除键等非打印元素；
> · 表体左缩进 4.76mm（Word 件 tblInd 270 dxa），宽度取「可印区 − 缩进」，右侧不被裁；
> · 防截断 + 能分页：单元格 `overflow:visible`、短行 avoid、照片行允许跨页、单张照片不切断。

2. 预览页顶部可改检查单位 / 验收单位（下次默认沿用）、上传现场照片（≤3 张，自动压到 1000px，存进隐患台账 `photos`）。
   「验收单位」只影响正文那句「整改完成后报××验收」，纸面验收单位栏留白手写
3. 正文可直接点开改（contenteditable），改完再出件
4. **打印**：浏览器打印对话框，纸张已按 A4 排版；**出件后自动写一条流转留痕**（可取消勾选）。
   对话框若出现网址/日期/页码，在「更多设置」里取消「页眉和页脚」——这是浏览器行为，CSS 关不掉
5. **保存为 Word**：生成 `.docx`（真 OOXML，Word / WPS 直接打开、可再编辑），
   文件名 **`事故隐患整改通知书（2026.10.22）.docx`**（出件当天日期，月日不补零）；
   ★ **不加任何后缀**：同一天再出第二份也叫同一个名字。
   ★ 文件名里**不带隐患编号**（纸质件归档不暴露内部编号）。
   走 Word 打印天然没有页眉页脚，也方便签字后扫描归档。照片是网页内嵌图，Word 里改为占位提示，需要带图请用「打印」

> 正文只写**隐患部位 + 事实 + 整改措施 + 完工期限 + 报验单位**，
> **不写编号 / 等级 / 类型**——这些是内部管理信息，留在系统台账里，纸质件只给责任单位签收执行。

**留痕内容**：`下发《事故隐患整改通知书》：要求 {责任部门} 于 {期限} 前完成整改，责任人 {责任人}。`

> 打印走浏览器 `@media print`，只输出通知书纸张：工具栏、删除照片按钮一律不上纸质件。

### 照片怎么存：不压缩 + 大图外置（2026-10-24）

**为什么改**：培训 / 隐患照片要能下载原图取证，压到 1000px 会丢细节。但浏览器 localStorage 每个源只有约 **5MB**，
一张手机照 3~6MB，两三张就写不进去（会报「本地存储已满」）。

**做法**（`components/photoVault.js`，对视图代码零侵入）：

- **落盘时**：业务数据里所有 `data:image/...` 且长度 > 30KB 的字符串，写进 **IndexedDB**，JSON 里只留 `vault:<key>` 引用
  → localStorage 只剩几十 KB，容量上限从 5MB 变成 IndexedDB 的几百 MB
- **启动时**：把 `vault:<key>` 全部换回 dataURL → 内存里仍是完整图片，**视图 / 打印 / 水印 / 导出照旧拿 dataURL，一行没改**
- 同一张图按内容指纹复用同一个 key，重复保存不会堆积
- 「清空数据 / 重置示例」时一并清空仓库，不留孤儿

**降级与兜底**：
- 浏览器不支持 IndexedDB（如隐私模式）→ 自动退回「整包写 localStorage」，行为与以前一致
- 引用丢了（换浏览器、清过站点数据）→ 显示「照片丢失」占位图，**不破图、不崩页**

**导出备份**：备份 JSON 里是**完整原图**，文件会明显变大（几条带照片的记录可能几十 MB），属正常现象。

**历史照片**：2026-10-24 之前上传的是压缩版，**无法还原成原图**；新上传的才是手机原图。

## 二·十三、证件图片识别（接公司 OCR 接口，2026-10-24）

**做什么**：特种作业人员台账 →「操作 ▾ → 编辑」→ 弹窗顶部点 **「识别图片」**，
自动读「证件照」里第一张图上的文字，把姓名 / 作业类别 / 操作项目 / 证书编号 / 发证机关 /
有效期起止 / 复审日期 **直接填进对应字段**，填完可逐项手改。

**为什么需要接口**：本项目是零依赖的离线单页，浏览器本身没有中文 OCR 能力（体积与离线要求也放不下）。
所以识别这一步交给一个 HTTP 接口，拿到文字后由本地规则 `components/ocr.js` 拆成字段——**解析这一步断网也能跑**。
接口有两种来源，二选一，页面代码完全不用改：
- **本机离线服务（默认，开箱即用）**：随项目附带的 `safety-desk_dev/local_ocr_server.py`（RapidOCR 模型，纯 CPU、不联网）
- **公司 OCR 接口**：腾讯云 / 百度 / 内网 OCR，配置见下方第 1 节

### 0) 开箱即用：本机离线识别服务（推荐，零成本、不联网）

```bash
# 首次装依赖（约 100MB，模型随包内置）
python -m pip install rapidocr-onnxruntime -i https://mirrors.aliyun.com/pypi/simple/
python -m pip install "onnxruntime==1.20.1"        # 重要：1.21+ 在本机会 DLL 初始化失败

# 启动服务（只监听 127.0.0.1:8123，不对外、不上传图片）
python safety-desk_dev/local_ocr_server.py
```

- 启动后打印 `本地识别服务已启动：http://127.0.0.1:8123`，**用页面期间保持窗口开着**
- 页面 `config.js` 已指向它（`endpoint: 'http://127.0.0.1:8123/ocr'`），不用再改
- 探活：`http://127.0.0.1:8123/health` 应返回 `{"ok":true,...}`
- 停止：窗口按 `Ctrl+C`；换端口：`set OCR_PORT=8124` 再启动
- 实测：模型加载 0.6s，单张证件约 1~2.5 秒；整页截图约 4~5 秒

> 本机服务与公司接口是同一套约定（`POST /ocr {"image": base64}` → `{"text": "..."}`），
> 以后公司接口就绪，只把 `endpoint` 换掉即可。

### 0.5) 一键启动：页面按钮直接拉起服务（注册一次，推荐）

不用再记着「先开一个窗口」：页面会自己把服务拉起来。

```bash
# 一次性注册（写 HKCU，不需要管理员；随时可卸载）
双击 safety-desk_dev/install_ocr_protocol.bat
```

之后在 **特种作业人员 →「操作 ▾ → 编辑」** 弹窗顶部：

| 状态点 | 含义 | 你能做什么 |
|---|---|---|
| ● 识别服务在线（绿） | `/health` 通 | 直接点「识别图片」 |
| ● 识别服务未启动（红） | 服务没跑 | 点旁边的 **「启动服务」**；或直接点「识别图片」，会先自动拉起再识别 |
| ● 正在启动识别服务（黄闪） | 正在拉起 / 等就绪 | 等 2~4 秒，状态自动变绿 |
| ● 公司识别接口（蓝） | 用的是外网接口 | 不探活、不启动，行为与以前一致 |

**首次点「启动服务」**会弹浏览器的「打开 WorkBuddy Local OCR Service?」——选 **打开**
（勾选「始终允许」以后不再问）。这是浏览器对外部协议的安全确认，只能点一次。

**原理**：注册了 `safetyocr://` 自定义协议 → 页面在点击的同步栈里触发协议 →
Windows 执行 `start_ocr_silent.bat`（已在运行就直接退出，不会起第二份；最小化窗口，日志写 `_ocr_server.log`）→
页面轮询 `/health`，就绪后自动继续识别（默认最多等 25 秒）。

**日常操作**：
- 停止服务：双击 `safety-desk_dev/stop_ocr.bat`（静默启动没有窗口可关）
- 卸载一键启动：双击 `uninstall_ocr_protocol.bat`（识别本身不受影响，改回双击 `start_ocr.bat` 手动启动）
- 协议没注册：点「启动服务」会在 25 秒后明确提示「去双击 install_ocr_protocol.bat 或 start_ocr.bat」，不会静默失败
- 换机器 / 换 Python 环境：重新双击 `install_ocr_protocol.bat`（自动记录当前 Python 路径到 `_python.txt`）

### 1) 配置（一处，改完即生效）

`assets/js/config.js` → `SD.CONFIG.ocr`：

| 字段 | 说明 |
|---|---|
| `endpoint` | 识别接口地址。**默认已填本机服务** `'http://127.0.0.1:8123/ocr'`；换公司接口就改成 `'/api/ocr'`（同域）或 `'https://gw.company.com/ai/ocr'`。**留空 = 未配置**：按钮仍在，点击会明确提示来这里配，不会静默失败 |
| `mode` | `'json'`（默认，base64 走 JSON）或 `'form'`（multipart 上传文件） |
| `fieldName` | 图片字段名，默认 `image` |
| `headers` | 鉴权头，例 `{ Authorization: 'Bearer xxx' }` |
| `textPath` | 返回 JSON 里文字所在路径，默认 `text`；若是 `{data:{text}}` 就填 `data.text` |
| `extra` | 需要随图上传的额外参数（并入 json body） |
| `timeout` | 识别超时，默认 15s（比普通接口慢，单独给） |

### 2) 接口约定（默认 json 模式）

```
POST  {endpoint}
Content-Type: application/json          (+ headers 里的鉴权头)
Body  { "image": "<base64，不含 data: 前缀>" }

返回  { "text": "识别出的整段文字" }
```

返回结构不用改也能用（已做兜底）：`{data:{text}}`、`{result:{text}}`、
百度的 `{words_result:[{words}]}`、腾讯整页识别的 `{data:{text_lines:[{text}]}}`、
以及纯文本响应都可以。**换服务商只改 config，不改代码。**

> ⚠️ **跨域**：页面会直接从浏览器请求该接口，接口必须允许页面来源（`Access-Control-Allow-Origin`），
> 否则会被浏览器拦（控制台报 CORS）。最省事的是把接口和页面放同域（如 `/api/ocr` 反向代理到 OCR 服务）；
> 也**不要在页面里放云厂商的 SecretKey**，签名放后端做。

### 3) 识别不到时怎么办

- 没上传证件照 → 提示「请先在「证件照」里添加一张证件图片」；
- 没配接口 → 提示去 `config.js` 配 `endpoint`；
- 接口报错 / 超时 / 返回没文字 → 弹出具体原因（HTTP 码、超时、返回结构），提示条里也留一行；
- 识别到文字但没匹配上字段 → 明确说「没匹配到台账字段」，提示换一张正面清晰照。

**绝不静默**，也**绝不伪造识别结果**：所有填入的都是接口真实返回并经本地规则解析的值。

### 4) 解析规则覆盖（`components/ocr.js`）

| 字段 | 识别依据 |
|---|---|
| 姓名 | 「姓名 / 姓 名」后的 2~4 个汉字；OCR 插入的空格（如「李　强」）会被合并，遇「性别 / 出生 / 作业」等词自动截断 |
| 证书编号 | 「证号 / 证书编号 / 编号」后的字母数字串（≥6 位，转大写） |
| 作业类别 | 「作业类别」→ 映射到台账 11 类字典；没有该行时用「准操项目」反推（如「低压电工作业」→「电工作业」、「起重机械指挥」→「吊装作业」） |

| 有效期起 / 止 | `2020-01-15 至 2026-01-14`、`2020年1月15日至2026年1月14日`、`2020.1.15-2026.1.14` 都能认，统一转成 `YYYY-MM-DD` |

全角数字 / 全角冒号 / 中文括号会先归一化再匹配；识别不到的字段**保留原值不动**，不覆盖已有正确内容。

打印时不会漏到第二页。

**白夜班两张表各一页（★ 2026-11-04）**：导出不再只看当前班次 —— 点「导出 Excel（白夜班）」后，
把**当前日期**的「白班」「夜班」两张表各出一个 sheet（sheet 名 `2026-11-04 白班` / `2026-11-04 夜班`），
每个 sheet **各自缩放到恰好一页**（A4 横向 + fitToPage），打印即第 1 页白班、第 2 页夜班，
双击打印选「双面打印」正好正反面。
★ 为什么是两个 sheet 而不是「一个 sheet 分行」：fitToPage（缩成一页）与行分页符在 Excel 里互斥——
设了 fitToPage 会把两张表 48 行硬缩成一页、分页符失效；不设 fitToPage 则每张 24 行的表本身超一页、
会裂成 2~3 页。所以「一页一张表」只能靠两个 sheet 各自 fitToPage 实现。

### 为什么以前一页装不下（2026-10-25 定位的三个原因，已修）

参考表是 Excel，它在文件里存了 `fitToPage`，**打印那一刻**会把整张表等比缩到 83.6% 塞进一页；
浏览器没有这个机制，必须靠 CSS 的布局级缩放自己算。以前不行是因为三件事叠加：

| # | 原因 | 实测证据 |
|---|---|---|
| 1 | **纸张误用了通知书的 `.pn-sheet` 类**。`print.css` 在 `components.css` 之后加载、优先级相同，把 `.sl-sheet` 的 `248mm 宽 / 0 内边距 / 160mm 最小高` 覆盖成 `210mm / 24.8mm / 297mm` | 纸张实测 **794×1230px = 210×325mm**（A4 纵向比例），表格被挤到 160mm 宽，文字大量折行，需要缩到 53% 才勉强塞下 |
| 2 | **缩放把「只改画面」的 `transform` 当成了首选**。原来用 `scrollHeight` 判断 `zoom` 是否生效，而 Chrome 里加了 `zoom` 后 `scrollHeight` **仍报未缩放值** → 永远判成"不支持" → 退回 `transform`。`transform` 不改布局，打印分页仍按原尺寸算 | 同一份 DOM：`zoom` 输出 **1 页**，`transform` 输出 **2 页**（真打印 PDF 数页数） |
| 3 | **行高被全局行距撑高**。`base.css` 的 `line-height:1.55` 让 11pt 文字行盒 22.7px，加 1.4mm 上下内边距 → 每行撑到 **26pt**（应为 24pt），19 行多出 38pt；另有 3 个 4 字分组名（危化品区/发泡区域/特种设备）在 9 字符宽的 B 列里差 0.3px 就折行，各多 12pt | 逐行量：19 行里有 3 行是 49px(36.75pt)、其余 32px(24pt)，总高 850px（应为 777px） |

修完实测（真打印成 PDF，数页数）：纸张 **964×795px = 255×210mm**、缩放 **80%** → **1 页 / A4 横向（297×210mm）**，
19 行 + 抬头 + 表尾注 + 备注全部在页内，无截断。

**★ 2026-10-25 修掉的第四个真 bug**（保存页「漏了班次和时间」的根因）：
抬头行第一个格子 `mergeAcross:2` 合并成 A:C，而后面的「班次」「日期」两个格子**仍按顺序落到 B、C 列**，
正好被合并一口吃掉 —— 导出的表里只剩厂区/部门/巡检人员。现在 `xlsxWriter` 支持单元格显式列位
`cell.col`（0 起），这两个格子钉在 D、E 列，`mergeAcross` 也算它们自己的位置，不会再被吞。

**★ 2026-10-25 修掉的三个真 bug**（都是出件"内容缺失 / 错位 / 少边框"的根因）：

1. **后半张表整体左移一格**：检查项列、备注列被纵向合并的行少 push 了格位，
   而 `xlsxWriter` 是按数组顺序往 A/B/C… 落的 → 从第 2 组开始「检查内容」跑到 B 列、「检查情况」跑到 C 列，
   D / E 两列连单元格都没有（既错位又缺右边框）。现在被合并掉的列一律补 `{v:'', border:true}` 占位格，
   **19 个明细行每行都占满 A~E 五格**，自检逐行核对列位。
2. **明细行行高把长内容截掉**：原表一律 20.5pt，但最长的两条检查内容（特种设备 / 电气）一行放不下。
   现在按估算行数放宽（放不下就给 36pt），**宁可高一点也不丢字**。
3. **第一个用到的样式被丢**：`xlsxWriter` 的样式索引从 0 起，而写出时只在 `s>0` 时写 `s` 属性 →
   第一格（正好是标题）的 16pt 加粗居中全部失效。现在 0 号留给默认样式，实际样式从 1 号开始。

另外按你的要求：**标题行与厂区行（抬头行）在界面、打印件、导出件三处都是「无边框 + 居中」**。

**权限**：受限用户也能**看、打印、导出**；只有安全员能改检查情况与备注（受限态下下拉是禁用的，顶部有「只能查看」提示）。

**字段**（`data/schema.md` 的 `shiftLogs`）：`id / date / shift / inspector / checks[]（19 项，每项 '' / 'ok' / 'bad'）/ events[]（备注事件文本数组）/ updatedAt`。

  `startIdleWatch / checkIdle`，也可用 `SD.app.idle.check()` 手动触发（自检就是这么测的）。

## 二·十八、列表默认「按年查看」（2026-11-04）

**背景**：台账跑了几年后，隐患 / 巡检 / 培训 / 通知的列表会越滚越长，当年的事被往年淹掉。
现在这四页**默认只列当年**的记录，顶部筛选条里多一个「年份」下拉，可切到任意有数据的年份，非当年时旁边出现「回到今年」。

| 页面 | 控件位置 | 归年字段（口径） |
|---|---|---|
| 隐患管理 | 状态 chips 右侧 | `foundDate`（发现日期）；老数据缺发现日期回退 `dueDate` |
| 安全巡检 | 范围 chips 右侧 | `scheduledDate`（计划日期） |
| 安全培训 | 状态 chips 右侧 | `startDate`（开始日期）；缺了回退 `endDate` |
| 通知公告 | 卡片标题右侧（搜索框前） | `publishAt`（发布日期） |

**控件长这样**：`年份 [2026 年 ▾] 2026 年 共 12 条 · 全部 46 条`，非当年时中间多一个「回到今年」。
下拉里只列**数据中出现过的年份 + 当年**（不会给你一堆空年份去点）；当年那条永远在，哪怕当年一条记录都没有。

**几条刻意定死的规则**：

- **刷新即回当年**：年份只存在内存的 `state.filters` 里，不写本地存储 —— 浏览器刷新 / 第二天打开都默认当年，
  不会「上次翻到 2024 年，这次打开看不到今年的记录」。
- **只是视图过滤**：不写库、不改数据；导航摘要与首页指标（`metrics.js`）仍是**全量**口径。
  但**页内的指标卡 / chips 计数跟着所选年份走**（培训四张卡、通知副标题、隐患与巡检的「共 N 条」），
  否则「未开始 5 条」点进去只有 3 条，看着像 bug。
- **巡检的「本周」例外**：范围 chip 停在「本周」时不套年份 —— 跨年那一周（如 12-29~01-04）硬套年份会把
  上一年那几天砍掉，与「本周完成率」指标卡对不上。在「本周」下改年份会**自动切到「全部」**，
  免得选了半天没反应。
- **归不到年份的记录不丢**：字段全空的老记录归入**当年**，宁可归错年也不让记录从列表里消失。
- **空年份有出口**：切到没数据的年份，列表给「2024 年还没有隐患记录」+「回到今年」按钮，不会只留一片空白。
- **打印 / 导出不受影响**：隐患整改通知书、日报周报等出件仍按各自口径取数。

**代码**：共用组件 `assets/js/components/yearBar.js`（`yearOf / yearOfRecord / yearsOf / build`），
四个视图各配一行 `YEAR_FIELDS` 声明归年字段，样式在 `components.css` 的 `.year-fg`（窄屏整行 + 44px 触控）。

### 2) 常用功能：统计全部菜单，只展示前六

侧栏「常用功能」= **全菜单使用频率排行榜的前 6 名**，不再是一组写死的快捷按钮
（旧版是「登记隐患 / 待办任务 / 巡检打卡 / 安全培训 / 数据看板 / 导出台账」6 个固定项，只在它们内部排名）。
纯本机统计，不联网、不上传、不跨设备。

**统计范围**

- **计入**：`router.ROUTES` 里全部 **15 个页面级功能** —— 安全概览 / 待办任务 / 隐患管理 / 安全巡检 /
  安全培训 / 数据看板 / 通知公告 / 日报 / 周报 / 交接班记录 / 违章考核单 / 特种作业 /
  特种作业人员 / 特种设备人员 / 危险作业票。路由表就是唯一口径来源，以后加页面自动纳入。
- **不计**：「报表」「更多」这类只做折叠、没有独立落点的父菜单；导出 / 打印 / 导入等按钮动作（不是菜单项）。
- **不计（但照常记录次数）**：当前角色打不开的功能——受限模式下特种作业 4 项
  不排名、不占名额，避免侧栏出现「点了一直弹无权限」的入口；切回安全员后立刻参与排名。

**排序规则（三级键，逐级比较）**

1. **使用次数**从多到少；
2. 次数相同 → **最近一次使用时间**从新到旧；
3. 再相同 → **菜单内置顺序**（`router.ROUTES` 里的位置）。

第 3 级是「定序兜底」：同次数的一批功能每次渲染都落在同一位置，不会因为遍历顺序不同而左右横跳。

**并列怎么处理**

- 三级键一定比得出先后，所以**第 6 名永远只有一席**，不存在「两个第 6 该放谁」的歧义。
- 名次只给**用过的**功能（次数 > 0）编；次数与最近使用时间都相同的算并列，名次跳号（1、1、3）。
- **0 次的项不排名**，弹窗里名次显示「—」；它们只是按菜单顺序**补位**填满前六，标记为「补位」而不是「前六」。
- 与第 6 名同次数但被挤出去的，侧栏底部直接写明「**另有 N 项同为 X 次，未进前六**」，不悄悄吞掉信息。

**数据为空时**

- 一条记录都没有（新设备 / 清空过统计 / 隐私模式写不进 localStorage）→ **不显示空白区**，
  按菜单顺序展示前 6 项，底部注明「暂无使用记录，按菜单默认顺序展示」。
- 弹窗顶部同步标注「暂无使用记录」，合计 0 次，占比列显示「—」，不会出现 `NaN%` 或空白格。

**计数与存储**

- **计数口径**：进一次功能记 1 次，key 与路由 id 对齐（`hazard` / `inspection` / …），
  导航、侧栏磁贴、页面内跳转都算同一个功能——统计的是**功能**热度，不是某个按钮的点击量。
- **防刷**：只在**用户主动切到另一页**时 +1；**首屏自动落地的那一页不计**（那不是用户的选择，
  算进去会让「安全概览」永久霸榜），同一页反复刷新 / 改筛选也不重复计。
- **存哪**：本机 `localStorage` 的 **`sd_usage_v1`**（`{v,counts,last}`），只存这台设备；
  隐私模式写不进去时退化成内存计数，不影响使用。
- **怎么看**：鼠标悬停任一磁贴，`title` 写着「第 N 名 · 本机用过 M 次（最近 今天 HH:mm）」；
  点标题旁的小问号 → 弹出「**功能使用统计**」，列出全部 15 项的名次 / 次数 / 占比 / 最近使用
  与四条口径（统计范围 / 排序规则 / 并列处理 / 空数据），底部可「清空统计」。
- **怎么重置**：弹窗里的「清空统计」，或清空浏览器站点数据，或控制台 `SD.usage.reset()`。

**实现位置**：口径与算法在 `assets/js/usage.js`（`RULES` 文案 + `board()` 排名看板），
侧栏渲染与弹窗在 `app.js`（`quickCatalog` / `renderSidebarQuick` / `openUsageStats`）。
弹窗是只读的，用 `dialog.open({ hideCancel:true, readonly:true })`：只留一个「关闭」，
且关闭键用 ghost 样式——受限模式的写操作守卫会拦 `.btn.primary`，用 primary 会「点了关不掉」。

## 二·二十四、巡检「巡查照片」更名「隐患照片」+ 看板隐患计数改为按部门照片汇总（2026-11-10，v1.3.1）

**两条需求**：① 安全巡检「新增巡检任务」里「巡查照片」统一更名「隐患照片」，

### 一、为什么更名是合理的

巡检拍下来的照片本质就是**隐患现场证据**，原来叫「巡查照片」，
与其它模块的「隐患照片」叫法不统一，且与看板想统计的「隐患数量」脱节。
改完之后，表单、列表、执行记录、看板四处说的是同一件事。

### 二、字段更名，但**存储键不改**

| 项目 | 处理 |
|---|---|
| 显示名 | 「巡查照片」→「隐患照片」（表单 label、帮助文案、列表 title、执行记录弹窗、无照片提示） |
| 存储键 | **仍是 `photos`**，一行没动 |
| 老数据 | 零迁移：历史巡检记录、已导入的备份、跨机迁移指纹里的 `photos` 照常读写 |
| 为什么 | 改键名要同时做迁移脚本 + 兼容读取 + 备份导入改造，收益为零；显示名改一处、统计口径归一处在 `metrics` 里就够了 |

`views/inspection.js` 的字段定义处写了醒目注释，明确「存储键仍是 photos，不要改」，
防止后人误改。

### 三、看板口径怎么改的

**新增** `metrics.inspectionPhotos(data)`，四件事一次算清：

| 口径 | 规则 |
|---|---|
| 统计对象 | `data.inspections[].photos` 的**张数**（不是 `record.hazardCount` 条数，两者不是一回事） |
| 部门归属 | 巡检任务的「责任部门」；**空值归「未指定部门」**，保证各部门相加 === 总张数 |
| 时间归属 | 按 `scheduledDate`（计划日期）归月，与巡检列表「归年」口径一致 |
| 任务状态 | **不排除**：改期 / 取消的任务，已上传照片仍计入（照片是现场证据，不随任务状态消失） |
| 无照片任务 | 不进任何口径（既不计张数，也不计任务数） |

**看板上的变化**

| 位置 | 变化 |
|---|---|
| KPI 第一张 | 「隐患总数」→「隐患照片」= 巡检照片总张数，副文案「N 项巡检任务上传」 |
| 「各部门隐患趋势」 | → 「**各部门隐患照片趋势**」：近 12 个月按部门照片张数折线 |
| 新增区块 | 「**各部门隐患照片**」：横向条形按照片数降序，每行「N 张（M 项）」，右上角写合计 |
| 隐患趋势 / 类型分布 / 等级分布 / 整改率 | **保持不变**，标题里写明「基于隐患台账」 |

### 四、一处必须讲清的边界：为什么闭环类指标没跟着改

照片**没有状态、也没有等级**，算不出闭环率、逾期、整改率。
如果硬把这些也换成照片口径，页面会出现「隐患总数 = 照片张数、已闭环 = 台账条数」
两套数字打架。所以最终是这样分工，并在页面「口径说明」里写成两段：

- **一、隐患照片（主口径）**：张数、按部门、按月的所有计数；
- **二、隐患台账（状态口径）**：闭环率、逾期未闭环、延期跟进、类型/等级分布、整改率。

两块在标题里分别注明，不混算。

另外补回了我在重写看板时误删的「隐患趋势」区块（原有功能，闭环观察要靠它），

## 二·二十五、受限模式的操作边界 + 巡检补「隐患类型」（2026-11-10，v1.3.2）

**三条需求**：① 受限状态下「待办任务」不可推进任务状态；② 受限状态下「交接班记录」不可导出；
③ 修改巡检任务编辑项，满足数据看板各卡片统计。

### 一、受限模式：待办任务不可推进

原来待办的「一键处理」按钮是 `.todo-check`，**不在写操作守卫的选择器里**，
所以受限用户点一下就能把隐患推进到下一状态、把巡检标记完成 —— 这是之前漏掉的口子。

改法三层：

| 层 | 做法 |
|---|---|
| 渲染 | `listItem.todo()` 新增 `canAct` 选项；`todo.js` 传 `SD.auth.can('data.write')`，受限时按钮渲染成 **disabled + 小锁图标 + 虚线边** |
| 事件 | `canAct === false` 时**根本不绑 onDone 回调** —— 不是靠拦截，是压根没有可执行的路径 |
| 兜底 | `app.js` 的 `WRITE_SEL` 加上 `.todo-check`，防止别处直接构造出可点的按钮 |

为什么用禁用态而不是「点了弹没权限」：受限用户在这个页面是**只读**的，
让按钮看起来就能点、点完再报错，等于拿报错当教程。禁用 + 小锁一眼就懂，
鼠标悬停有完整说明；手机上没 hover，所以页面底部「口径说明」里也加了一句
「当前为受限模式：本页只读，一键处理按钮已锁定，要推进请点右上角输入密码解锁」。

### 二、受限模式：交接班记录不可导出

| 层 | 做法 |
|---|---|
| 函数入口 | `exportXlsx()` 开头判断 `SD.auth.can('data.write')`，不满足就 toast 并 return —— **工具栏按钮、行操作菜单、以及以后新增的任何入口都会走到这里**，一处堵住最可靠 |
| 工具栏 | 导出按钮禁用 + `is-locked`（虚线边）+ 旁边一行小字「受限模式：可查看与打印，导出已锁定」 |
| 行菜单 | 「导出 Excel」「删除」两项在受限时标为禁用（`disabled`），文字加「（受限模式不可用）」 |
| 组件 | `dropdown.js` 补上「禁用项点击不执行、也不关菜单」—— 之前只有 `disabled` 属性、点了照样触发回调 |

**打印仍然保留**。打印是纸质留痕，不产生可编辑、可带走的数据文件；
用户要禁的是「把原始表导成 Excel 拿走」，不是禁止出纸。

> 顺带把行菜单的「删除」也在受限时禁掉了 —— 它和导出同属「能改数据」的操作，
> 而 `WRITE_SEL` 拦不到菜单项（菜单项是 `.dd-item` 不是 `.data-act`），属于同一类口子。

### 三、巡检补「隐患类型」，看板类型分布换成巡检口径

看板 8 张卡片里，照片 / 部门 / 趋势 3 张已经能靠巡检数据撑起来，
但「隐患类型分布」原来读的是隐患台账的 `type`，巡检侧没有对应字段，这张图在
「只用巡检、不登记台账」的场景下永远空白。

所以给巡检表单新增 **`hazardType` 隐患类型**（下拉，取 `dict.hazardType` 10 类）：

- **非必填**：正常无异常的巡检不该被逼着编一个类型；没填的归「未分类」但仍计入；
- **口径是「次数」不是「张数」**：一条有照片的巡检记一次，所以类型合计 = 有隐患照片的任务数，
  与照片张数不同（照片是证据，任务是事件）。这一点在卡片副标题和底部口径说明里都写明了；
- 看板「隐患类型分布」改为巡检口径，中心数字改用「隐患次数」；
- **「隐患等级分布」仍留在台账口径** —— 巡检没有等级字段，硬编号称就名不副实。
  两张环形图口径不同，副标题各自标注（「基于巡检」/「基于隐患台账」），不混算。

按用户确认：**闭环率、逾期、延期、整改率四张卡保留台账口径**（巡检没有整改状态机，
算不出闭环；给巡检加状态机等于再造一套隐患台账）。这也是页面上「二、隐患台账（状态口径）」
那一段存在的意义。

## 二·二十六、受限模式：**所有导出**一并收紧（2026-11-10，v1.3.3）

上一版只锁了「交接班导出」一处，其余导出口子照旧能用 —— 那些文件和交接班表一样能
把整份台账带走，等于给「受限」留了一道后门。按用户要求**全部收到一个能力点**。

### 一、口径：导出锁，打印留

| 动作 | 受限用户 | 为什么 |
|---|---|---|
| 查看 / 搜索 / 筛选 | ✅ | 复核现场要看数据 |
| **打印**（通知书 / 交接班表 / 照片页） | ✅ | 纸质留痕，不产生可编辑、可带走的文件 |
| **导出**（Excel / Word / 照片 / JSON 备份 / 导入模板） | ❌ 需六位密码 | 一个文件就能把整份台账带走 |

### 二、八处导出一张表

| # | 位置 | 控件 | 受限表现 |
|---|---|---|---|
| 1 | 顶栏「⋯ → 导出备份」 | JSON 全量备份 | 标锁定态 + `需解锁`，**仍可点**：点了先弹六位密码框，验过直接导（与相邻「导入」同一交互） |
| 2 | 特种设备人员台账 | 导出 Excel | 置灰 + 虚线边 + title 说明 |
| 3 | 特种作业人员台账 | 导出 Excel | 同上 |
| 4 | 日报 / 周报 | 生成 Excel | 置灰 + 旁边小字「受限模式：可查看与打印，导出已锁定」 |
| 5 | 巡检交接班 | 导出 Excel（白夜班） | 同上（工具栏 + 行菜单两处） |
| 6 | 隐患整改通知书 | 保存为 Word | 置灰，提示语改成「可打印，保存为 Word 已锁定」 |
| 7 | 作业票照片页 | 保存为 Word | 同上 |
| 8 | 培训「操作 ▾ → 下载照片」 | 水印弹窗（含原图 / 批量） | 菜单项禁用；弹窗入口直接拦下（唯一用途就是下载，不必让人调完水印再被拒） |

另：台账「下载导入模板」一并锁（模板只服务于导入，而导入本就需写权限）。

### 三、三层防护

| 层 | 位置 | 作用 |
|---|---|---|
| ① 视觉 | `SD.auth.lockBtn()` | 禁用 + `is-locked`（虚线边 + 半透明）+ title + `aria-disabled` |
| ② 兜底 | `app.js → installExportGuard()` | 捕获阶段拦所有 `[data-export]`，以后新加的导出按钮只要打这个标记就自动生效 |
| ③ 真拦 | 各导出函数入口 + `xlsxWriter.download()` / `docxWriter.download()` | 两个下载落点是**所有 Excel / Word 出件的唯一出口**，从这里再判一次，谁绕过都出不去 |

判定入口统一为 `SD.auth.canExport()`（= `can('data.export')`），
提示文案唯一口径 `SD.auth.DENY_EXPORT_MSG`，各处不再各写一句。

### 四、顺带补的两个写口子

通知书 / 作业票照片弹窗里的「上传照片」原来在受限下能点 —— 它走 `updateHazard` /
`updateWorkPermit` 会**改台账**，属写操作。现在受限时置灰（打印预览里的照片仍可看）。
台账「导入 Excel」也拦在弹窗门口，不再出现「进来只能对着灰色按钮发呆」的死对话框。
