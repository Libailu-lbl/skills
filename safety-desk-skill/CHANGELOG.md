## v1.3.6 — 巡检单支持「分部门问题明细」（2026-11-12）

**主题**：一张巡检单可以记录并查出多个部门的不同问题（按部门分别填问题内容 / 等级 / 条数 /
照片 / 整改），数据看板仍按部门正确汇总。要求**最小改动**，且历史数字一个不变。

### 一、数据模型：明细行是唯一真值

- 新增 `problems: [{ id, dept, content, type, level, count, photos[], fixDate, fixPhotos[] }]`。
- 顶层 `dept / hazardType / hazardCount / hazardLevel / photos / fixDate / fixPhotos`
  **降级为兼容镜像**（保存时按行汇总写回：首个非空部门、最高等级、条数之和、照片拼接）。
- 聚合只读行，镜像不参与累加 → 不会数两遍；而列表角标、灯箱、打印、导出、报表
  继续读顶层字段，**这些地方一行未改**。

### 二、老记录零迁移的等价性证明

`metrics.hazardRowsOf(t)` 在 `problems` 为空时返回**一条合成行**（取顶层原值）。
一条记录 = 一行，所以按行累加与改造前逐值相同。关键前提：

- `count` 走 `legacyCountOf`（含 `record.hazardCount` 兜底），防递归
- `hazardTasks` 保持**记录级**（一张单不论拆几个部门都只算 1 个任务）
- 未知等级键归一为 `''`，否则 `LEVEL_ORDER` 过滤后 `Σ byLevel < hazardCount`
- 整单整改状态按「有条数的行」聚合，纯照片行不参与判定

改造前 18 套 1317 项 → 改造后老用例**一条没改**，全部照绿。

### 三、口径增量

| 数 | 来源 |
|---|---|
| 照片**张数** | 各明细行 `photos` 之和 |
| 隐患**条数** | `Σ 各行 count` |
| 隐患**处数** | **有照片的明细行数**（老记录 = 该任务） |

「处数」与「任务数」在多部门单上不再相等（一单 3 部门、2 个带照片 → 处 2 / 任务 1），
看板「合计 N 张 / M 项」在两者不等时补一句「（共 R 项任务）」；
类型环图的中心与图例统一用**处数**，否则会出现「图例合计 2、中心写 1」。

### 四、表单：多部门是可选模式

- 新增组件 `assets/js/components/problemRows.js`（行编辑器，`mount(host,{value,depts,actions,onChange})`）。
- **默认仍是单部门表单**，只多一个「＋ 按部门拆分」；点了才把当前表单值灌成第 1 行并隐藏 7 个标量字段。
- 明确不改进 `formDialog`（缺重复行、字段级渲染钩子、多值读取、行级校验四处能力），
  改用它的表单级 `onMount` 挂载 —— 十种既有字段零回归。
- 行内禁用 `ff_*` 前缀 id（否则主表单照片会串行）；删除行用「再点一次」，不开嵌套弹窗
  （dialog 的 ESC 是模块级单变量，嵌套会误关父表单）。

### 五、修掉三个真问题

1. 待办页「一键完成」写死 `hazardCount: 0` → 把已填条数清零（数据损坏级）。
2. 多部门单若仍渲染 `#i_hz`，「标记完成」弹窗 `parseInt('')` 得 `NaN`，永远报错关不掉。
3. 「0 条但有照片」的行会从照片口径消失 —— 条数与照片两套过滤条件必须分开写死。

### 六、自检

- `smoke_inspection_photos` 114 → **160 项**、`smoke_blank` 162 → **164 项**。
- 18 套 **1365 项** 全绿；骨架 19 项照旧。
- 390px 实测 `scrollWidth === clientWidth === 390`，明细字段单列堆叠、无横向溢出。

## v1.3.5 — 巡检 × 数据看板：统一数据来源与统计口径（2026-11-11）

**主题**：让「巡检记录 / 隐患条数 / 整改状态」在看板与巡检页同源同值。
用户定调：只统一口径、版式不动；隐患数量用人工填写的**条数**；整改状态不加字段、按证据推导；
日报周报本轮不动。

### 一、一个函数，两页共用
- 新增 `metrics.inspectionStats(data, today)` = 巡检侧**唯一**统计入口：
  `{records, byStatus, weekRate, hazardCount, hazardTasks, byLevel, byDept, fix, fixTasks, fixRate}`。
- 巡检页顶部汇总条与看板「安全巡检（隐患与整改）」段都只读它 → 数值一致是结构保证。
- `metrics.hazardCountOf(t)`：顶层 `hazardCount` 优先 → `record.hazardCount` 兜底 → 0。

### 二、口径（三套数，页面三处写清）
| 数 | 来源 | 用在哪 |
|---|---|---|
| 照片**张数** | `photos[].length` | KPI 首卡、各部门隐患照片 |
| 隐患**条数** | `Σ hazardCount`（人工填） | 看板隐患条数、巡检页汇总条、整改率分母 |
| 隐患**次数** | 有照片的任务数 | 隐患类型分布 |

- 整改状态派生：`fixDate` 非空 = 已整改 / 只有 `fixPhotos` = 整改中 / 都没有 = 未整改。
- 三态**按条数**累计（`none+doing+done === hazardCount`）；整改率 = 已整改 / 隐患条数。
- 只有条数 > 0 的任务进整改口径（没发现问题 ≠ 未整改）。
- 等级分布按 `hazardLevel` 分组、value = 该组 Σ 条数 → `Σ byLevel === hazardCount`。
- 不筛任务状态；空部门归「未指定部门」，`Σ byDept.hazardCount === hazardCount`。

### 三、字段映射
- 巡检新增 `hazardLevel`（enum，空=未定级），`hazardCount` 改为两个入口都能填且**顶层为唯一口径**。
- `record.hazardCount` 降级为兼容镜像；`dataSource.completeInspection` 双写。
- 「标记完成」弹窗补等级下拉，条数初值取已有值（原来写死 0）。

### 四、修掉三个真问题
1. 老记录编辑**清零**条数（`values` 未注入 `hazardCountOf`）→ 已注入 + 三处双写。
2. 下拉无空项 → 未填等级被静默回填「重大」、未填类型被回填「消防」（`formDialog` 默认选首项）→ 两处前置空值项。
3. 图表 tooltip 单位错（照片趋势显示「条」、类型环图硬编码「条」）→ `chart.donut` 支持 `unit`。
4. 附：`summary.trend` 从死数据改为 `hazardTrend()` 现算（全 0 仍回空态）。

### 五、边界
- 不合并页面、不重排看板原有 8 段、不改导航（路由仍 15 条）。
- 不新增 `fixStatus` 字段；不做「一条隐患一行」子表（后续方向）。
- **日报 / 周报不动**：仍按 `completedAt` 归周，与看板「按计划日期」的差异**已知且记录在案**。
- 巡检隐患不自动生成台账记录：两本账，不互相折算。

### 自检
- `smoke_inspection_photos` 66 → **114 项**（+48）；`smoke_blank` 156 → **162 项**（+6）。
- 18 套 **1317 项**全绿；骨架 19 项照旧。

## v1.3.4 — 看板推进锁定 + 巡检补「整改照片 / 整改日期」（2026-11-11）

**主题**：① 安全概览页「安全重要工作」在受限状态下不能推进状态；
② 安全巡检编辑里增加「整改照片」和「整改日期」。

### 一、看板：受限不能推进状态
推进有两条路（卡片按钮 + 桌面拖拽），一起锁；三层都做：

| 层 | 做法 |
|---|---|
| 渲染 | 推进按钮 `disabled + is-locked`（虚线边 + 浅灰底）+ **小锁图标** + title；卡片 `draggable="false"`；看板上方常驻说明条（`.kw-lock`），副标题改「受限模式下只能看，不能推进」 |
| 事件 | `click` 命中 `[data-act="advance"]` 先判权限（兜「强解 disabled」）；`dragstart` 直接 `preventDefault`，`drop` 到不了 `moveTo` |
| 函数入口 | `advance()` / `moveTo()` 各判 `SD.auth.can('data.write')`，程序内直调也改不动 |

- 与「待办任务」页锁定口径一致（那页锁 `.todo-check`）：**禁用 + 小锁 + 一句说明**，
  不是「点了再报没权限」——受限用户在这一页是只读的，报错当教程不合适。
- 手机没有 hover，所以另加常驻说明条；打印时说明条隐藏（`@media print`）。
- 新增 / 编辑 / 删除本来就由 `data-write` + 写操作守卫拦，本次不动。

### 二、巡检：新增 `fixDate` / `fixPhotos`
- `fixDate`（日期）：整改**完成**的日期，与「计划日期」相互独立。
- `fixPhotos[]`（照片，≤18 张）：整改**后**的现场照片，原图保存、大图自动外置。
- **与 `photos`（隐患照片 = 整改前）分开存**：证据链两端，混存就分不清前后、也没法各自计数。
- **不进看板「隐患照片」口径**：`metrics.inspectionPhotos` 只读 `photos`，整改照片不计入张数 /
  部门汇总 / 类型分布，避免同一件事被数两遍；页面「口径说明」与字段 help 都写明了。
- 执行记录弹窗新增两行：整改日期 + 「查看 N 张整改照片」（点开大图）。
- 兼容：存量记录无这两个字段 → 读取处 `|| []` / `|| ''` 兜底，打开编辑空值不报错，**零迁移**；
  photoVault 按 `data:image/` 长串扫描外置，与字段名无关，`fixPhotos` 自动生效。

### 自检
- `smoke_keyworks` 56 → **71 项**（+15：按钮 disabled / is-locked / 小锁 / title、说明条、draggable=false、
  强解 disabled 不推进、dragstart 取消、drop 不改状态、解锁后全部恢复）。
- `smoke_inspection_photos` 46 → **66 项**（+20：两字段存在、日期控件、非必填、照片上限 18、
  与隐患照片互不串、老记录空值、两套照片各自落库、看板口径不受污染、执行记录展示）。

## v1.3.3 — 受限模式：**所有导出**一并收紧（2026-11-10）

**主题**：v1.3.2 只锁了「交接班导出」，其余导出口子照旧能用 —— 那些文件和交接班表一样能把
整份台账带走，等于给「受限」留了后门。本版把所有出件收到 `data.export` 一个能力点上。

### 一、口径：导出锁，打印留
| 动作 | 受限用户 | 理由 |
|---|---|---|
| 查看 / 搜索 / 筛选 | ✅ | 复核现场要看数据 |
| 打印（通知书 / 交接班表 / 照片页） | ✅ | 纸质留痕，不产生可编辑、可带走的文件 |
| 导出（Excel / Word / 照片 / JSON 备份 / 导入模板） | ❌ 要六位密码 | 一个文件就能把整份台账带走 |

### 二、收紧的八处导出
顶栏「导出备份」、设备人员台账、特种作业人员台账、日报 / 周报、交接班（工具栏 + 行菜单）、
隐患通知书「保存为 Word」、作业票照片页「保存为 Word」、培训「下载照片」（水印弹窗含原图 / 批量），
另加台账「下载导入模板」。

- 顶栏「导出备份」保留**可点**：点了先弹六位密码框，验过直接导（与相邻「导入」同一交互）；
- 模块内导出按钮统一 `disabled + is-locked`（虚线边 + 半透明）+ title + 旁注原因；
- 通知书 / 照片页只锁 Word 不锁打印，工具栏提示语改成「可打印，保存为 Word 已锁定」；
- 培训「下载照片」菜单项禁用；弹窗入口直接拦下（唯一用途就是下载，不必让人调完水印再被拒）。

### 三、三层防护
| 层 | 位置 | 作用 |
|---|---|---|
| ① 视觉 | `auth.lockBtn()` / `unlockBtn()` | 禁用 + `is-locked` + aria + title |
| ② 兜底 | `app.js → installExportGuard()` | 捕获阶段拦所有 `[data-export]`，新按钮打标记即生效 |
| ③ 真拦 | 各导出函数入口 + `xlsxWriter.download()` / `docxWriter.download()` | 两个下载落点是 Excel / Word 出件的唯一出口，绕过按钮也出不去 |

判定统一 `SD.auth.canExport()`（= `can('data.export')`），提示文案唯一口径 `SD.auth.DENY_EXPORT_MSG`。
能力点从 4 个增到 5 个（新增 `data.export`），受限角色仍只有 `data.read`。

### 四、顺带补的三个写口子
- 通知书 / 照片页弹窗的「上传现场照片」受限下置灰（走 `updateHazard` / `updateWorkPermit`，属写操作）；
- 台账「导入 Excel」拦在弹窗门口（原来能进弹窗，只能对着灰按钮发呆）；
- 交接班导出的判定从 `data.write` 换成 `data.export`，与「导出」口径对齐。

### 自检
- 新增 `tests/smoke_export_gate.js` **71 项**：逐处验证「受限被拦 + 解锁通行」，
  并直接调两个下载落点验证第三层拦得住。
- 原有 17 套全部复跑（导出相关用例均在解锁态执行，不受影响）；
  `scripts/run_all_tests.sh` 已把新套件加入，共 **18 套 / 1228 项**。

## v1.3.2 — 受限模式操作边界 + 巡检补「隐患类型」（2026-11-10）

**主题**：三条需求 —— ① 受限状态下待办任务不可推进状态；② 受限状态下交接班记录不可导出；
③ 修改巡检任务编辑项以满足数据看板各卡片统计。

### 一、受限模式：待办任务不可推进
原来待办「一键处理」按钮是 `.todo-check`，**不在写操作守卫选择器里**，受限用户点一下就能
推进隐患状态、标记巡检完成 —— 之前漏掉的口子。
- `listItem.todo()` 新增 `canAct` 选项，受限时渲染成 **disabled + 小锁 + 虚线边**；
- `canAct === false` 时**不绑 onDone 回调**（不是靠拦截，是压根没有执行路径）；
- `WRITE_SEL` 加上 `.todo-check` 兜底；
- 页面「口径说明」在受限时多一段说明，手机上没有 hover 也能看懂为什么点不了。

### 二、受限模式：交接班记录不可导出
- `exportXlsx()` **函数入口**判权限，不满足就 toast + return —— 工具栏、行菜单、
  以后新增的入口都会走到这里，一处堵住最可靠；
- 工具栏按钮禁用 + `is-locked`（虚线边）+ 旁注「受限模式：可查看与打印，导出已锁定」；
- 行菜单「导出 Excel」「删除」受限时 disabled，文字加「（受限模式不可用）」；
- `dropdown.js` 修：禁用项点击不执行、也不关菜单（原来只有 disabled 属性，点了照样触发）。
- **打印保留** —— 纸面留痕不产生可带走的数据文件；要禁的是「把原始表导成 Excel 拿走」。

### 三、巡检补「隐患类型」，看板类型分布换口径
- `views/inspection.js` 新增 `hazardType` 字段（下拉，`dict.hazardType` 10 类），**非必填**，
  没填归「未分类」仍计入；`submit` 落库。
- `metrics.inspectionPhotos()` 增加 `byType`：按**次数**统计（一条有照片的巡检记一次），
  合计 = 有隐患照片的任务数，**不等于照片张数**（照片是证据，任务是事件）。
- 看板「隐患类型分布」改为巡检口径，中心数字改「隐患次数」；「隐患等级分布」仍留台账口径
  （巡检无等级字段），两张图副标题分别标注口径，不混算。
- 按用户确认，**闭环率 / 逾期 / 延期 / 整改率保留台账口径** —— 巡检没有整改状态机，
  算不出闭环；给它加状态机等于再造一套隐患台账。
- `data/schema.md` 补 `hazardType` 字段与类型分布口径说明。

- `smoke_inspection_photos` 34 → **46 项**（隐患类型字段、下拉选项、非必填、byType 分组、
  未分类归集、合计 = 任务数、看板类型分布改口径）。

## v1.3.1 — 巡检「巡查照片」更名「隐患照片」+ 看板隐患计数改为按部门照片汇总（2026-11-10）

**主题**：两条需求一起落地 —— ① 安全巡检「新增巡检任务」里「巡查照片」统一更名「隐患照片」；
② 数据看板的隐患计数改为「按各部门统计巡检任务上传的隐患照片数量」汇总展示。

**为什么更名合理**：巡检拍的照片本质就是隐患现场证据，原名与其它模块的「隐患照片」叫法不统一，
也与看板要统计的「隐患数量」脱节。改完后表单、列表、执行记录、看板四处说的是同一件事。

### 变更
- `views/inspection.js`：字段 label「巡查照片」→「隐患照片」，同步改帮助文案、列表区域列 title、
  执行记录弹窗标签、无照片提示。**存储键仍是 `photos`**，一行没动 —— 历史记录、已导入的备份、
  跨机迁移指纹全部零迁移；字段定义处写了醒目注释「存储键不要改」防止后人误改。
- `metrics.js` 新增 `inspectionPhotos(data)`，口径五条：
  统计 `inspections[].photos` 的**张数**（不是 `record.hazardCount` 条数）｜部门取「责任部门」、
  空值归**未指定部门**（保证各部门相加 === 总张数）｜按 `scheduledDate` 归月｜
