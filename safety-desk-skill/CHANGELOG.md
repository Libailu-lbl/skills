## v1.3.0 — 概览页「今天要处理」换成「安全重要工作」四列看板（2026-11-10）

**主题**：安全概览页原来的「今天要处理」是一列纵向清单，只能看、只能点完成。
现按用户提供的独立看板原型（`safety-board.html`）改成**四列状态看板**：
待开始 / 进行中 / 待验收 / 已完成，卡片带类别、优先级、负责人、截止时间与推进按钮，
配统计条、筛选栏，支持新增 / 编辑 / 删除 / 拖拽换列。视觉一律用工作台既有变量，
不引入任何外部样式与库。

### 变更
- **新增** `assets/js/components/keyBoard.js`：看板组件（渲染 / 筛选 / 排序 / 表单 / 推进 / 拖拽）。
- `views/overview.js`：删掉整段「今天要处理」渲染（含「查看全部 N 项」、空态、超 6 条提示），
  改为 `SD.comp.keyBoard.render(host, ctx)`。
  **自动推导的待办没有消失** —— 它们仍在「待办任务」页，概览顶部「待办事项」指标卡也还在。
- **数据**：新增集合 `keyWorks`（`initial.js` 补空数组、`store.DATA_KEYS` 收录 → 现 13 类、
  `metrics.summarize` 透传、`dataSource.js` 四个语义函数 `list/create/update/removeKeyWork`）。
  它进导出备份、进导入白名单、进跨机迁移对数。
- **样式**：`components.css` 追加 `.kw-*`（统计条 / 四列 / 卡片 / 逾期与临期徽标 / 推进按钮），

### 口径

## v1.2.8 — 备份导入漏项修复 + 跨机迁移配套（2026-11-06）

**主题**：编写跨机迁移方案时逐项盘点数据链路，发现一个会**静默丢数据**的缺陷——
`store.js` 的 `importJSON()` 重建 `data` 时白名单只列了 11 个集合，
漏掉 `devicePersonnel`（特种设备人员台账）与 `shiftLogs`（交接班记录）。
用「导出备份 → 导入恢复」搬数据到另一台电脑，这两类台账会消失，
而 `load()` 又会自动补空数组，界面看起来一切正常，很难察觉。

### 变更
- `load()` 与 `importJSON()` 改为共用同一份 `DATA_KEYS` 唯一清单（12 类）；
  新增集合只改一处，杜绝「一处改了另一处漏改」。
- `importJSON()` 按清单逐类搬运，12 类集合一类不落；编号校验逻辑不变。
- 清单导出为 `SD.store.DATA_KEYS`，供迁移脚本读取做两机数据指纹比对。
- `smoke_blank.js` 新增 5 项回归：造一份 12 类齐全的备份导入，验证
  `devicePersonnel` / `shiftLogs` 未丢、原有台账仍在、清单覆盖 12 类。

### 跨机迁移配套（工作区交付，未入仓库）
- 《安全员工作台跨机迁移方案与验收清单.docx》：8 章 + 3 附录 + 20 项可勾选验收签字表，
  覆盖迁移内容清单、12 步流程、11 类环境差异与兼容对策、六层验证方法、回滚预案。
- `safety-desk-migrate/` 脚本包（8 文件，零依赖）：旧机导出偏好、新机恢复偏好、
  两机生成数据指纹、命令行比对（PASS/FAIL）、63 文件 SHA256 清单、一键启动本地服务。
- 关键结论：GitHub 里的 `examples/safety-desk-blank` 是**脱敏版**（9 文件不同），
  只能当异地代码备份；代码必须整目录拷贝，数据必须走「页面 JSON 备份 + 补迁 6 个偏好键」，
  两机要固定同一 origin（建议 `http://127.0.0.1:8124`）。

## v1.2.7 — 常用功能改为「全菜单排名 · 只取前六」

**主题**：侧栏「常用功能」原来是一组写死的 6 个快捷动作（登记隐患 / 待办任务 / 巡检打卡 /
安全培训 / 数据看板 / 导出台账），只在它们内部按次数排名——菜单里其它 10 个功能用得再多也进不来。
现在改成**统计全部菜单**，按频率排名后只展示前 6 名，并把这套口径写进界面与文档。

### 变更
- `usage.js` 新增 `board(list, limit)`：一次给出「前 N 名 + 其余 + 不可用项 + 是否空数据 + 并列落选数」，
  并把四条口径收进 `SD.usage.RULES`（统计范围 / 排序规则 / 并列处理 / 空数据），
  tooltip、弹窗、README 共用同一份文案。
- 统计范围：`router.ROUTES` 全部 **15 个页面级功能**（含特种作业 3 个子页）。
  「报表」「更多」只做折叠、没有落点，不计；导出 / 打印等按钮动作不计。
  当前角色打不开的功能**照常记次数但不排名、不占名额**（避免侧栏出现点了没反应的入口）。
- 排序三级键：次数 ↓ → 最近使用 ↓ → 菜单内置顺序 ↑。第三级是定序兜底，
  同次数的一批功能每次渲染位置一致，不会左右横跳。
- 并列：名次只给用过的功能编，次数与最近使用时间都相同算并列（名次跳号 1、1、3）；
  0 次的项不排名，弹窗显示「—」并按菜单顺序**补位**（标记为「补位」而不是「前六」）；
  与第 6 名同次数但落选的，侧栏底部注明「另有 N 项同为 X 次，未进前六」。
- 空数据：一条记录都没有时按菜单顺序展示前 6 项 + 底部注明「暂无使用记录，按菜单默认顺序展示」，
  不留空白区；弹窗同步标注、占比显示「—」（不会出现 `NaN%`）。
- `app.js` 计数改为**不算首屏落地页**：只有用户主动切页才 +1（否则「安全概览」会永久霸榜）；
  同页刷新 / 重绘仍不重复计。
- `router.js` 给交接班记录、违章考核单补 `short` 短名（磁贴窄，全名会换行）。
- 点标题旁小问号 → 弹窗「功能使用统计」：15 项名次 / 次数 / 占比 / 最近使用 + 四条口径 + 「清空统计」。
- `dialog.js` 新增 `hideCancel` 与 `readonly` 两个选项：只读弹窗只留一个「关闭」，
  且关闭键用 ghost —— 受限模式的写操作守卫会拦 `.btn.primary`，用 primary 会「点了关不掉」。

### 自检
- `smoke_nav` 68 → **88 项**：15 项统计范围、只展示 6、三级排序（含同次数比最近使用）、
  7 项同次数时的落选注明、空数据默认顺序与脚注、首屏落地不计、受限模式剔除 4 项且次数仍保留、

## v1.2.5 — 取消导航下拉的悬停展开，只保留点击

**主题**：悬停自动展开容易误触——鼠标沿侧栏往下划，整列菜单会被逐个弹开；鼠标移开又会自己收起，
和「点击展开」的语义也冲突。改为**只有点击才开合**。

### 变更
- `router.js` 的 `dropNode` 删除 `mouseenter` / `mouseleave` 监听，连同 `data-hover`、`data-pin` 一套状态一并移除；
  现在展开/收起的唯一入口就是点击父项（另一种进入方式是切页时按当前页自动展开所属分支）。
- 鼠标移入 / 移出**不触发任何动作**：收起状态移入不展开，展开状态移出不收起；
  也不会出现延迟展开/收起（没有残留定时器）。
- 保留不变：同级互斥（同一时间只开一个）、箭头旋转 + `aria-expanded`、`.in-tree` / `.active` 高亮、
  `Esc` 一键全收、换页自动展开所属分支、同页重绘保留手动开合、父项有落地页时点击顺带进入。
- 视觉上的 hover 背景高亮仍由 CSS `:hover` 负责，不受影响。

### 自检
- `smoke_nav` 59 → **63 项**：原「悬停展开 / 移开收起」一组改写为「悬停不触发开合」——
  收起态移入不展开（再等 400ms 仍不展开）、移出不变化、展开态移出不收起、移入保持、
  只有点击才收起，并断言 DOM 上不再有 `data-pin` / `data-hover` 痕迹
- 空白版 **995 项**（15 套）、骨架 **19 项**，全绿
